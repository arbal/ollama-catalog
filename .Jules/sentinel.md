## 2024-05-18 - Prevent path traversal in URL construction
**Vulnerability:** The `detect_url` method in `model_scraper.py` blindly trusts the `slug` input when constructing URLs (e.g., `f"https://ollama.com/{slug}"`). This allows an attacker to provide a malicious slug like `../../evil` which could lead to Server-Side Request Forgery (SSRF) or arbitrary URL fetching. Additionally, special characters are not URL encoded.
**Learning:** Even internal tool components that seem to deal with "safe" string identifiers must treat all external data (like model slugs from the internet) as untrusted. `urllib.parse.quote` should be used for escaping, and explicit checks against `..` are necessary because `quote` does not encode periods.
**Prevention:** Always validate identifiers by rejecting invalid patterns (e.g., directory traversal sequences like `..`) and properly URL encode them using `urllib.parse.quote(slug, safe="/")` before interpolating into URLs.

## 2026-09-15 - Prevent Git command argument injection
**Vulnerability:** The `git_show` wrapper in `scripts/explore_catalog.py` directly interpolated untrusted input into a `subprocess.run` command array (`["git", "show", f"{ref}:{path}"]`). While array formulation prevents shell injection, an attacker could supply a reference starting with `-` (e.g., `--output=/tmp/pwn`) leading to argument injection that `git show` interprets as flags.
**Learning:** Array-based `subprocess` execution protects against shell metacharacters but does not prevent argument injection if the invoked program parses the interpolated string as an option flag. The `--` end-of-options delimiter is typically used, but in `git show <ref>:<path>`, `--` causes Git to interpret the string as a pathspec instead of a revision.
**Prevention:** Explicitly validate that user-provided arguments do not begin with a hyphen (`-`) before passing them to commands where end-of-options delimiters are inapplicable or change the parsing context.
