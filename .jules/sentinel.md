## 2024-05-24 - Path Traversal in Slug Handling
**Vulnerability:** The codebase constructs URLs using string formatting with the `slug` variable: `f"https://ollama.com/{slug}"` and `f"https://ollama.com/library/{slug}"`. Since `slug` is derived from an untrusted source (Ollama website search results, but conceptually user-controlled input), an attacker could inject `../` to cause path traversal. Even worse, `urllib.parse.quote` might encode other chars but will not stop an explicit check for path traversal dots `..` if malicious. Actually `slug` could be manipulated if this was taking input from a web UI. Wait, this repo scrapes from `https://ollama.com`. `slug` is parsed from `<a href="/namespace/model">` which is somewhat trusted, but still good practice to validate it. Let me check how slugs are derived.
**Learning:** `detect_url` uses string formatting without URL encoding or validation.
**Prevention:** Use `urllib.parse.quote(slug, safe='/')` and prevent path traversal by checking for `..` in the slug.
